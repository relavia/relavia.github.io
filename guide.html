使用教程

按你的情况选一篇就行。什么都不懂、只想先连上，看第一篇；手里有订阅地址，看第二篇；连不上，先翻第三篇自查。剩下的都是可选进阶，不看不影响使用。

一、免配置上手：用免费池子先连上

不需要准备任何东西，也不用懂任何术语。跟着下面四步走完，就能先连上、用起来。

  1. 第一步：启用免费节点来源

    打开 app，进入「导入」页，在「节点来源」里找到 VPN Gate，点它进入。

  2. 第二步：读完风险提示，点确认

    屏幕上会先出现一整页说明：这些节点是志愿者用自己的电脑提供的，连接记录会被保留、也可能依法被披露。看懂之后点确认，节点来源才会打开——这一步绕不过去，是故意设的。

  3. 第三步：点「刷新」，等节点出现

    刷新后，节点列表里会出现一批带国旗和国家名的节点。不用自己挑，下一步让 app 替你挑。

  4. 第四步：点「自动选择」，再点「连接」

    app 会把节点逐个测速，挑出最快的一个连上；状态变成「已连接」就是通了。觉得慢时，断开后再点一次「自动选择」，它会重新测一遍。

必须说清楚：池子节点运行在志愿者的个人电脑上，连接日志按其政策保留三个月以上并可依法披露，运营者能接触经其转发的未加密流量。它解决的是「能不能连上」，不是「隐不隐秘」：一般浏览可以，账号口令、财务信息等敏感内容不要走它。有自己的节点时，优先用自己的（见第二篇）。详情见 VPN Gate 风险说明页。

设置里还有一个「协议偏好」，一般不用管，保持「自动」即可。

二、用订阅地址导入自己的节点

如果你已经在用某个服务商，它给你的订阅地址就是最省事的入口：贴一次，以后节点更新了，回来点一下刷新就行。

  1. 第一步：复制订阅地址

    就是服务商给你的那条以 http:// 或 https:// 开头的长链接，一般在服务商后台的「订阅 / 一键导入」处可以复制。整条复制，不要漏字。

  2. 第二步：贴进「订阅地址」框，别贴进文本框

    「导入」页上方有专门的订阅地址输入框。注意它下面那个大文本框是留给单条分享链接的：把订阅地址贴进文本框，app 会把它当作普通链接解析，结果只会是「失败 1 个」。贴错不丢人，换个框重贴就好。

  3. 第三步：点「添加并拉取」

    app 会顺着订阅地址把节点全部拉回来，按分组出现在节点列表里。万一拉取失败，导入页会直接写明原因；更细的记录在「日志」页里。

  4. 第四步：选节点连接

    看中哪个点哪个，再点「连接」；拿不准就点「自动选择」，让 app 按测速替你挑。之后节点有变动，回到导入页对这条订阅点「刷新」，不用重新粘贴。

支持的订阅格式：sing-box JSON、Clash / mihomo YAML、V2Ray base64、纯链接列表。主流服务商给的地址基本都能直接用。

三、连不上时先自查

下面几条覆盖了大多数「连不上」。按你屏幕上看到的现象对号入座；都对不上时，去 app 的「日志」页——每次失败的时间、环节和原因都记在那里，反馈问题时把那几行一并贴出，定位快得多。

屏幕上的现象 多半是为什么 怎么办

导入结果：成功 0 个，失败 1 个

把订阅地址贴进了文本框，或把分享链接贴进了订阅框——两个框收的东西不一样

看清框上方的标题，换个框重贴：订阅地址进订阅框，ss://、vless:// 这类链接进文本框

点连接后转一会儿，报错断开

这个节点当前连不通：下线、被封或临时故障，池子节点尤其常见

换一个节点试试，或点「自动选择」让 app 挑测速最快的再连

池子里的节点一个都连不上

池子是志愿者的电脑，随时开关机；也可能是你当前网络到这些地址的线路不通

先点「刷新」拉一份新名单，过几分钟再试；仍不行，改用自己的订阅节点（第二篇）

订阅拉取失败

订阅地址失效、套餐到期或流量用尽，也可能只是当时网络不通

回服务商后台重新复制最新地址再贴一次；仍失败，去「日志」页看这次失败记下的具体原因

点了连接，先弹出风险说明

你还没确认过 VPN Gate 的风险提示。池子节点在确认之前一律不让连，这是故意设的门，不是故障

把说明读完点确认即可；只弹这一次，之后可在来源设置里随时撤销

这一节写给有自建节点、或愿意自己调参数的人。只用池子和订阅的，这一节完全可以不看。

用文件导入

服务商或自建服务器给的是文件时用这种方式：OpenVPN 的 .ovpn、WireGuard 的 .conf，或整份订阅文件，在「导入」页选「从文件导入」挑中文件即可。下面是两个文件的样例长相（示例内容，密钥均为假值）：

[Interface]
PrivateKey = EXAMPLE_PRIVATE_KEY_NOT_REAL
Address = 10.66.66.2/32
DNS = 1.1.1.1

[Peer]
PublicKey = EXAMPLE_PUBLIC_KEY_NOT_REAL
Endpoint = 203.0.113.16:51820
AllowedIPs = 0.0.0.0/0
client
dev tun
proto udp
remote 203.0.113.17 1194
auth SHA256
cipher AES-256-GCM
<ca>
-----BEGIN CERTIFICATE-----
(example certificate omitted)
-----END CERTIFICATE-----
</ca>

协议偏好：只影响「自动选择」怎么挑

它在设置页里，只在你点「自动选择」时起作用：测速接近的节点之间，它决定先挑哪一类协议。平时保持「自动」即可，下面是三种取向的对照：

偏好 适合什么时候

自动（推荐）

只看测速，延迟低的优先。绝大多数人、绝大多数情况，用这个。

速度优先

测速接近时，优先 WireGuard、Hysteria2、TUIC 这类较新的高速协议。节点很多、想榨性能，或者老协议在你的网络里总被限速时，试它。

兼容优先

测速接近时，优先 Shadowsocks、Trojan、VMess、OpenVPN 这类传统协议。新协议在你的网络环境里经常连不通、握手失败时，用这个更稳。

放心：如果当前分组里没有你偏好的那类节点，app 会自动退回按测速选，并在界面上注明，不会因为一个偏好设置就变得无节点可用。

进阶排查

屏幕上的现象 多半是为什么 怎么办

导入的 .ovpn 点连接立刻被拒

配置里带了这个客户端不支持的指令，或证书、密钥段不完整

去「日志」页看被拒的具体原因；对照服务商说明补齐配置。仍然不行，把日志里那几行贴到 GitHub Issues 问

节点旁标着「弱加密」警告

它用的是老式加密算法（例如 Shadowsocks 的 cfb、rc4-md5），安全性不足

可以留作存档备用，但别日常使用；自动选择也不会优先选它。能换的话，在服务端换成现代算法

反馈问题时，带上日志

「日志」页记着每次失败的时间、环节与真实原因，只存在你本机、不会上传。到 GitHub Issues 反馈时，把出问题那几行一并贴出，比只说一句「连不上」定位快得多。
