验签教程：确认你下载的包是真的

我们的安装包没有商业代码签名，所以验证不靠系统弹窗，靠你自己能复算的两样东西：SHA-256 哈希与 Ed25519 签名。下面两条路任选其一，第二条更完整。

路线一：比对 SHA-256（不用装任何工具）

在 Releases 页把安装包和同版本的 SHA256SUMS 下载到同一个文件夹。Windows 在该文件夹打开 PowerShell，执行第一条命令，把输出的哈希与 SHA256SUMS 里对应行逐字比对；Linux / macOS 打开终端，执行后两条命令之一：

# Windows (PowerShell)
Get-FileHash .\relavia-windows-amd64.exe -Algorithm SHA256

# Linux
sha256sum -c SHA256SUMS

# macOS
shasum -a 256 -c SHA256SUMS

每个文件都报告 OK（或手动比对一致），说明你拿到的字节与发布时完全一致。出现 FAILED 或哈希对不上，请不要安装，并把情况发到 GitHub Issues。

路线二：用 releasetool 验签（推荐）

需要 git 和 Go 工具链。验证工具 releasetool 就在代码仓库里，从源码构建它，不需要信任任何预编译文件：

git clone https://github.com/relavia/relavia.git
cd relavia/tools/releasetool
go build -o releasetool .

再下载同版本的更新清单 update-stable.json（Beta 为 update-beta.json）与发行公钥 release-pubkey.txt，和安装包放在同一个文件夹，在该文件夹执行：

./releasetool verify --manifest update-stable.json --pubkey release-pubkey.txt --dir .

看到每个产物一行 signature OK, file hash OK、末行 manifest OK，就是通过。工具还会打印发行公钥指纹（SHA256:…）——请与下载页公布的指纹逐字比对；指纹对不上，前面的 OK 也作废，不要安装。

客户端会自己做同样的事

通过客户端内更新拿到的版本，会自动执行同一套校验（先比文件大小与 SHA-256，再验清单上的 Ed25519 签名），被篡改或被换成旧版本的包会被拒绝并删除下载文件。手动验签与自动验签，是同一条信任链的两个入口。

想再深一层？

主仓库的《复现构建验证指南》（docs/复现构建验证指南.md）还给出第二层验证：从源码按与发布相同的提交重新构建并比对哈希，证明你下载的文件就是这份源码编译出来的。
