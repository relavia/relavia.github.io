使用教程

快速上手

Relavia 不内置任何节点。先准备好你自己的节点——自建服务器，或你信任的服务商给你的配置——再用下面任一方式导入客户端：

  1. 方式一：粘贴分享链接

    把 ss://、vless://、trojan:// 等分享链接粘贴到客户端的导入框，一次可以贴多条；剪贴板里现成的链接也能被识别导入。

  2. 方式二：订阅链接

    把订阅 URL 添加为订阅源即可导入，之后可随时刷新更新节点。支持的订阅格式：sing-box JSON、Clash / mihomo YAML、V2Ray base64、纯链接列表。

  3. 方式三：导入文件

    .ovpn、WireGuard 的 .conf 以及订阅文件，都可以直接作为文件导入。

  4. 方式四：扫码导入

    尚在开发中，暂不可用；现阶段请用粘贴链接代替。

关于弱加密节点：导入老式 Shadowsocks 节点（cfb、rc4-md5 等）时，客户端会明确给出警告。这类节点可以留作存量存档，但不应日常使用，客户端也不会自动优先选它。

导入后，选中节点、点击连接即可使用。连不上时，先看该节点的测活结果与错误信息，再对照常见问题页。

路由与 DNS

三种路由模式：全局（全部流量走节点）、规则（按规则分流，默认）、直连清单（只有名单内的流量走节点）。规则可按域名、域名后缀或关键字、IP 段、端口、协议组合；你显式写的规则永远优先于内置规则。

DNS 与路由使用同一套策略推导：走代理的域名交给经隧道的远程解析器，不回落本地运营商的明文 DNS；只有被明确设为直连的域名才用本地解析。fake-ip 默认关闭。

IPv6 有三档：开启、仅隧道、关闭。TUN 模式默认「仅隧道」，系统代理模式默认「开启」；选「关闭」时，IPv6 流量会被硬性拒绝，而不是漏出去。

WebRTC 与浏览器（如实说明）

先说实话：客户端不能代管浏览器内部的 WebRTC 行为。任何宣称「客户端已完全堵住 WebRTC 泄露」的说法都是不实的，我们不这样写。

TUN 模式下，WebRTC 的 STUN/UDP 流量与其它流量一样进入隧道、由路由规则裁决；如果节点不支持 UDP 中继，WebRTC 连接会失败，而不是偷偷改走直连。

系统代理模式下，浏览器只把遵循代理的流量交给客户端，WebRTC 的 UDP 探测可能绕过代理、暴露你真实的出口 IP。要防这一项只能改浏览器设置，客户端无权代劳：Firefox 可在 about:config 中把 media.peerconnection.enabled 设为 false；Chrome / Edge 可用企业策略 WebRtcIPHandlingPolicy（设为 disable_non_proxied_udp）或浏览器商店的 WebRTC 控制类扩展。改完后，建议打开任意一个 WebRTC 泄露检测页，对比连接前后的公网 IP 是否与隧道出口一致，亲眼验证。
